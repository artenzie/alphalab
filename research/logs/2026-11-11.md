## Lessons
- **Never type keys into code.** A key in a source file ends up in git history, backups and screenshots. Load it from `.env` and gitignore that file. If a key ever leaks, regenerate it.
- **Set up `.gitignore` before the first `git add`.** Once a file is committed it stays in history, even if you delete it later.
- **Why the rules matter:**
  - Future data in agent inputs (look-ahead bias) makes backtest and paper results look better than they really are.
  - An append-only decision log and frozen prompts make the experiment auditable. Results can't be tuned after the fact.
  - Asking for a plan before touching the ledger, snapshot or protocol protects the data that every result is built on.

- **`sudo` and interactive logins need a real terminal.** Commands run through Claude Code's `!` prefix can't answer password or login prompts. Run those in a separate terminal.
- **Public repo means anything committed is public, forever.** Scan the whole history, not just the latest commit, before the first push.
