## Agent harness (Phase 3 task, done early)

**Protocol v1.9** first (§5): AI agents (7–15) target only the 22 stocks. SPY stays in their snapshot as market context; a target on SPY is invalid output ("SPY is context only").

**Built:**
- `agents/llm.py`: `LLMClient` interface (`complete(prompt, model_id, provider, temperature, reasoning) -> LLMResponse` with text, model id, provider served, tokens in/out, cost, latency). `LLMUnavailable` and `LLMCapped` exceptions. `FakeClient` replays a script and records every prompt. No real API calls yet; OpenRouter client next session.
- `agents/harness.py`: `AIAgent(snapshot, portfolio, context) -> AIDecision`, the same call as agents 1–6. `AIDecision` is a `Decision` with a `record` (not part of equality): final status + one `AttemptRecord` per call. `AttemptRecord.row()` gives the decisions columns; the runner adds agent_id, snapshot_id, decided_at. No database, file, network or environment access.
- Prompt = template (placeholder until Sat 5 Dec) + `OUTPUT_SPEC` (complete portfolio, a held stock left out is sold, SPY context only) + compact JSON of date, snapshot fields, own portfolio (shares, weight, avg cost, unrealised P&L, return since start), own limits (from `execution.risk.profile`), last 5 decisions. sha256 of the exact prompt per attempt.
- Validation: bare JSON or one fenced block; NaN/Infinity and duplicate keys rejected; only the 22 stocks; finite numeric weights (not bool/string); a reason per target; confidence in [0, 1] (required for a rebalance). Weight limits are left to the §6 risk checks.
- §8 calls: provider down → 3 retries after 5, 10, 15 min → hold `unavailable`. Invalid → one retry with the error appended → hold `invalid`. Capped → hold `capped`, no retry. Unexpected exceptions propagate (a bug, not an outage).

**Design choices:**
- The §4 inputs a `Portfolio` doesn't carry (avg cost, starting value, last decisions) come in on a new optional `Context.memory` (`AgentMemory`, `PastDecision` in `strategies/base.py`), set by the runner. Rule-based agents ignore it; `build_context` is unchanged. Past decisions dated on or after the decision day raise (rule 1).
- A valid hold stores `parsed_targets` as the JSON text `null`, so the schema check "status ok needs parsed_targets" passes. Every attempt is its own row (attempt 1, 2, …), so a down-then-invalid day can have up to 8 rows.
- A response from the wrong provider is an `invalid` attempt; its retry resends the original prompt, since the model made no mistake.
- The model id logged is the one the provider reports; the requested id is in the call. Whether a mismatch is invalid is left for the OpenRouter session.

**Tests:** `tests/test_harness.py`, 49 tests: valid hold / rebalance / all cash, fenced JSON, bad symbol, SPY rejected (while SPY is in the prompt), missing reason, NaN / ±Infinity / 1e999 weights, bool and string weights, confidence out of range, malformed replies, retry-then-valid, retry-then-invalid, client down (sleeps 300/600/900), down then recovers, wrong provider, capped, prompt hash stable, prompt contents and limits, rows insert into a real decisions table, import check on `agents/*.py`, and the sealed run. Full suite: **453 passed**.

## OpenRouter adapter (Phase 3, Thu 3 Dec task, done early)

**Protocol v1.10 first** (§8, separate commit):
1. Each model is pinned to its maker's **standard endpoint** (`anthropic`, `openai`, `google-ai-studio` / `google-vertex`, `deepseek`, `xai`), not flex/fast/priority tiers. `require_parameters: true`, so an unsupported parameter is rejected instead of silently dropped.
2. **Max output 16,000 tokens** for all five, reasoning included. A reply cut off at the limit is invalid.
3. **Reasoning effort medium, set explicitly for all five.** "Each model's default" would have compared reasoning and non-reasoning models.
4. A reply that reports a model other than the requested id (or a dated variant of it) is invalid, like a wrong provider. Both ids are logged.

Temperature is unchanged: 0 for Gemini, DeepSeek and Grok. Claude and GPT accept no temperature on any endpoint (checked via `/models/{id}/endpoints`), so none is sent and the row records NULL.

**Built:**
- `agents/models.py` holds the lineup as data. `ModelConfig` has the model id, the provider names OpenRouter reports, the endpoint slugs to pin, temperature, reasoning and max_tokens. `AGENT_MODELS` maps 7, 8, 13, 14, 15 and C1 → Claude, and 9–12 → GPT, Gemini, DeepSeek, Grok. `scripts/test_pinned.py` now uses it.
- `agents/llm.py`: the `LLMClient.complete(prompt, model=ModelConfig)` interface. `model_matches(requested, reported)` accepts the exact id or a dated suffix (`-YYYYMMDD`, `-YYYY-MM-DD`, `-MMDD`, `@YYYYMMDD`). `LLMResponse` gains `reasoning_tokens` and `finish_reason`.
- `agents/harness.py`: `AIAgent(agent_id, model, template, client)`.
  - Invalid: a provider not in `provider_names`, a wrong model, or `finish_reason == "length"`.
  - A wrong provider or model is retried with the original prompt. A cut-off reply is retried with the error shown.
- `agents/openrouter.py`: `OpenRouterClient`.
  - 402 or a credit / spend-limit message → `LLMCapped`.
  - Timeout, connection error, 408, 429, 5xx → `LLMUnavailable`.
  - Anything else → `OpenRouterError(status)`, which is never retried.
  - Errors inside a 200 body are mapped by their code.
  - The key is read once via `os.getenv` and scrubbed from every message. Exceptions are not chained, and the repr hides the key.
- `pytest.ini` (`testpaths = tests`). **Found today:** without it, a plain `pytest` also collected `scripts/test_openrouter.py` and `scripts/test_pinned.py`, which make real API calls when imported. Past suite runs probably spent a few cents this way.

**Tests:** `tests/test_openrouter.py` uses a fake HTTP session. It covers:
- the request shape
- success parsing
- provider/model mismatch logged
- 402/limit → capped; 408/429/5xx/timeout/connection → unavailable; 400/401/403/404/422 → raises with status, one POST, no sleep
- a sentinel key never appears in an exception, log line or repr
- end to end through AIAgent

`tests/test_models.py` parses the §8 table (ids, makers, endpoints, reasoning, max output, temperature, the Claude agents). `tests/test_harness.py` adds wrong-model, dated-variant and cut-off cases. Full suite: **528 passed**.

## Crypto side agents C0 and C1, and the crypto fill price (Phase 3, Fri 4 Dec part 2, done early)

**Protocol v1.12.** A crypto order fills at the open of the **first 1-minute bar starting at or after max(00:15Z, the order's `created_at`)**, rounded up to the minute, plus the 0.25% fee and 5 bps.
- Artem chose this over a fixed 00:15Z bar. An AI call can return after 00:15Z, and a fixed bar would then fill at a price from before the order existed.
- For crypto, day D+1 fills decision D's orders and marks at D+1's daily close.

**What was built:**
- **`crypto_fill_bars`**: a new append-only table, kept separate from `prices` and never read by the snapshot.
  - It holds the closed minute bars from 00:15Z to 01:15Z after each decision.
  - Schema CHECKs reject a bar outside that window and a bar fetched before its minute ended.
  - It is versioned like the daily bars.
- **`data/fill_prices.py`**: fetches those bars (`--date` / `--start`).
  - Alpaca's crypto minute `end` is inclusive, so it asks up to 01:14.
  - A bad bar fails the run.
  - Heartbeats warn when a coin's first bar is more than 5 min late, or when it has no bar yet.
- **`ledger_db.settle_day`, crypto branch.** The equity path is unchanged; the ledger tests and the old-vs-new equity prompt comparison stay green.
  - Every calendar day is a settle day, and orders written before the day's close are filled.
  - The fill bar must have closed and been fetched by `now` (rule 11).
  - Fills use the fee, and so does the cash floor.
  - `filled_at` is the bar's `bar_ts`, and `fill_bar_id` goes in the fill detail.
  - `positions` rows now carry the agent's asset class; they were hard-coded `us_equity`.
- **C0**: `strategies/bitcoin.py`, in `registry.CRYPTO_AGENTS`.
- **C1**: `AIAgent("C1", model_for("C1"), CRYPTO_PLACEHOLDER_TEMPLATE, …)`. The harness now picks the crypto output spec for a crypto snapshot:
  - 5 coins, long only, and the limits key `max_per_coin`.
  - The equity prompts are byte-identical to before for agents 8, 14 and 15.
  - Agents and snapshots of different asset classes are refused.
  - The 50% cap and long only are enforced by `apply_risk("C1")`, tested end to end. An 80% BTC request becomes 50% and fills at 50%.
- **Tests: 584 passed.** They include a check that a crypto snapshot's hash is the same with or without minute bars stored.
